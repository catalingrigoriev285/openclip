# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

openclip is a cross-platform screen recorder in Rust (edition 2024, Rust 1.85+) with an egui/eframe GUI. It writes standard MP4 or AVI with **no external runtime dependencies**: OpenH264 and LAME are compiled from bundled sources by their crates at build time, hardware H.264/HEVC and AAC encoders come from Windows Media Foundation (part of the OS, Windows only), and the MP4 and AVI muxers are in-house. A C/C++ toolchain is required to build (MSVC on Windows; autotools on macOS/Linux — see README for the full package list). Installing `nasm` before building enables OpenH264's assembly kernels (~2× encoder throughput); without it the build silently falls back to C.

## Commands

```sh
cargo build --release                 # first build compiles OpenH264 + LAME from source (slow)
cargo run --release                   # launch the GUI
cargo test                            # unit tests + tests/mp4_roundtrip.rs + tests/avi_roundtrip.rs
cargo test --test mp4_roundtrip       # just the MP4 round-trip integration test
cargo test --test avi_roundtrip       # just the AVI round-trip integration test
cargo test --lib avc                  # run unit tests matching a name
cargo clippy --all-targets

# Headless examples (useful for testing the pipeline without the GUI)
cargo run --release --example capture_to_mp4 -- 10 out.mp4   # record primary monitor for 10 s
#   flags: --half --mic --no-audio --fx --region X,Y,W,H --window TITLE --pause-at S --resume-at S
#          --codec openh264|h264-hw|h264-sw|hevc|<label substring> --audio mp3|aac|pcm --avi --fps N --quality Q
cargo run --release --example bench_encode -- 1920 1080 5 out.mp4 --codec nvenc   # encoder throughput on synthetic content
cargo run --example list_encoders                            # every Media Foundation encoder + whether it activates
cargo run --example check_update                             # what the updater sees; `-- --install` runs the full self-update on the example exe
```

`profile.dev` uses `opt-level = 1` for the crate and `opt-level = 3` for dependencies, so debug builds are usable for real-time capture. In release builds `main.rs` sets `windows_subsystem = "windows"` (no console); use a debug build or `RUST_LOG` via `env_logger` when you need log output (`RUST_LOG=openclip=trace` also traces the Media Foundation event loop).

`.gitignore` excludes `*.mp4`, `*.avi`, `*.h264`, `*.wav`, `*.mp3` — examples and manual tests can write scratch media into the repo root safely.

## Architecture

The crate is a library (`src/lib.rs`) plus a thin binary (`src/main.rs`) that only builds the eframe window and instantiates `openclip::ui::App`. Examples and the integration tests link against the library API, so keep pipeline/codec code out of `ui`.

```
capture backend ──RawFrame──▶ encode thread: scale → I420/NV12 → VideoEncoder → Muxer (MP4 | AVI) ──▶ file
                                   ▲                                                    ▲
cpal (mic / loopback) ──▶ mixer ───┴──▶ AudioEncoder (MP3 | AAC | PCM) ─────────────────┘
```

### `src/i18n.rs` — interface language

Every user-facing string lives in one `strings!` table with an English, Romanian and Russian column; the macro generates both the `key::` constants and the lookup, so `t!(NAV_HOME)` is checked at compile time (`t!(KEY, a, b)` fills `{0}`/`{1}` and returns a `String`). The active `Lang` is a process-global `AtomicU8` — usable from the encode/audio threads, which is why `pipeline.rs` and the encoder fallback notes can be localized too. English is the fallback for a missing key. `Settings::load()` applies the saved `language`; the General page's Language combo calls `App::set_language` (sets it and saves). Unit tests assert every key resolves in all three languages and that translations keep the same `{n}` placeholders. Only display code calls `t!` — codec/container/profile identifiers (MP4, AAC, Baseline, …) and units stay untranslated. The UI font is Inter (bundled, see `theme.rs`), which covers Cyrillic and Romanian `ș`/`ț`; egui's default fonts stay registered as fallbacks.

### `src/settings.rs` — persisted user settings

`FormatSettings` is everything in the Format dialog: `Container` (Mp4/Avi), `SizeMode` (Full / Half / Preset / Percent, `resolve()` gives even output dims), `fps`, `VideoCodec` (`Auto` (default; `resolve_auto()` = first hardware H.264 else OpenH264), `OpenH264`, or `Mf { hevc, clsid }` — a Media Foundation transform identified by CLSID or `name:<url>`), `RateControl` (`Quality(10..=100)` → bitrate via `target_bitrate_kbps()`, or `ConstantBitrate`), keyframe interval, `Profiles`, `AudioCodec` (Mp3/Aac/Pcm), audio bitrate/channels/rate. `normalize(&available_encoders)` enforces the rules (PCM only in AVI, HEVC only in MP4, missing encoders → OpenH264, bitrate snapping) and returns user-facing notes. `Settings` (format + output dir, prefix, input toggles, mic name, `MouseFx`, countdown, `check_updates`) is saved as JSON **next to the executable** when that directory is writable or already holds `settings.json` (`choose_path()`), else in `dirs::config_dir()/openclip/`; `load()` never fails and falls back to the legacy per-user file. Dev builds therefore keep their settings in `target/debug` / `target/release`. `pick_encoder()` resolves CLI-style names for the examples.

### `src/update.rs` — update check and self-update

Blocking, egui-free, run on background threads by `ui/updater.rs`. `check()` GETs `api.github.com/repos/…/releases/latest` with `ureq` (rustls + `platform-verifier`, so the OS certificate store is trusted; 10 s timeout) and returns `Some(Release)` only when the tag is strictly newer than `local_version()` (`CARGO_PKG_VERSION`, overridable with `OPENCLIP_UPDATE_PRETEND_VERSION` for testing against a real release). `TARGET_SUFFIX` is the cfg-selected asset name suffix from the release workflow (`windows-x86_64.zip`, `linux-x86_64.tar.gz`, `macos-arm64.tar.gz`; `None` elsewhere), `pick_asset` matches `openclip-<ver>-<suffix>`. `download_and_install()` streams the asset to `.openclip-update-<pid>.<ext>` **next to the executable** (same volume), checks the size and the `sha256:` digest GitHub publishes per asset, extracts `BIN_NAME` from the nested folder into `<exe>.new` (zip on Windows, tar.gz on unix) and calls `self_replace::self_replace` (Windows: the running exe is renamed aside and a helper deletes it after exit); temp files are removed by a drop guard; `Progress` (downloaded bytes + cancel flag) is shared with the UI. `relaunch()` spawns the new exe directly (no shell → no console flash); the UI then closes the viewport. `install_dir_writable()` reuses `settings::dir_is_writable` (memoized). The UI side (`UpdateState` enum, threads, status-strip chip, About/General rows, modal) is `src/ui/updater.rs`; the modal is suppressed while the Format or delete dialog is open and install/restart need `State::Idle`.

### `src/pipeline.rs` — the recording session (`Recorder`)

The central orchestrator. `Recorder::start(RecordConfig, on_preview)` spawns:

- a **capture backend** (`capture::start`) whose sink pushes `RawFrame`s into a bounded `sync_channel(4)`; buffers come from a shared `FramePool` (returned by the encode thread); when the channel is full the frame is recycled and counted in `Stats::frames_dropped`;
- an **encode thread** (`encode_loop`) driven by a **`FrameClock`**: slot `k` has pts `pts0 + k/fps` (exact rational arithmetic). The loop drains the channel keeping only the newest frame (older ones → `frames_superseded`), waits for the slot deadline (`pts + interval/2`), then encodes one slot: the newest frame, or the previous frame again (`frames_repeated`) when nothing new arrived. If more than `FrameClock::MAX_BEHIND` slots are due it skips slots (`slots_skipped` — kept apart from `frames_dropped`, which means only "capture channel was full", so the two failures stay distinguishable); after a pause it `resync`s. `EncodeState::new` on the first frame resolves the output size, creates the encoder via `create_video_encoder` (fallback chain, note in `Stats::note`), a layout-matching `Converter` and the `Muxer`. Per slot: scale into a reused buffer (`downscale_half_into` / `Scaler::scale_into`), paint mouse effects **in place** (`MouseFx::paint` saves the touched rectangles, `restore` puts them back after conversion — no frame copy), BGRA/RGBA→I420/NV12 (skipped for unchanged repeats), encode (may return 0..n frames), mux; previews (`Previewer`, 5 Hz) only while the GUI reports the Preview tab visible (`Recorder::set_preview_visible`). The first video pts becomes `Stats::stream_start`, the timeline origin the audio thread waits on **and** the anchor `Recorder::elapsed()` measures from — the file contains nothing before it, so the timer and the GUI's fps must not count the start-up time (opening the audio devices alone is ~0.5 s; the encode thread logs it as `timeline starts at N ms`). `flush()` drains async encoders before `finalize`. `Recorder` holds a `TimerResolution` guard (`timeBeginPeriod(1)`) so waits are precise;
- an **audio thread** (if `wants_audio()`): opens the cpal streams **and creates the audio encoder** (Media Foundation objects are thread-affine) before reporting its `AudioTrackConfig` back; then cpal → `Mixer` → `AudioEncoder` → `AudioFrame` channel consumed by the encode thread's muxer. Mono is folded down from the mixer's stereo output.

**Timeline model:** every frame/chunk carries a timestamp relative to `epoch`. Pause is implemented by subtracting accumulated `paused_total_us` from timestamps (frames arriving while paused are discarded), so paused time is cut out of the file with A/V still in sync. Audio is mixed `AUDIO_LAG` (150 ms) behind wall-clock so device latency never creates gaps. `Stats` (atomics + `Mutex<Option<String>>` error / audio_note / note) is the only channel back to the GUI besides `PreviewSlot`.

### `src/player/` — playback for the library viewer

The read side of the pipeline, used only by `ui/viewer.rs`. `Player::open(path, repaint)` never fails: a file that cannot be decoded reports `PlaybackState::Failed`, and a non-Windows build reports `Unsupported`, which is what the GUI turns into an "Open in system player" fallback. The handle holds **no** COM object and no `cpal::Stream` — both are thread-affine and stay on the worker — so `Player` is `Send + Sync` and the GUI can own it.

- `decode.rs` (Windows): one `IMFSourceReader` with the first video **and** first audio stream selected. `ReadSample(ALL_STREAMS, ..)` reports the *real* stream index, not the `FIRST_*` sentinel, so both are resolved up front with a `GetNativeMediaType` sweep and kept as `Option<u32>` (a file may have only one). Video is negotiated to RGB32 — via the *advanced* video processor so `MF_MT_FRAME_SIZE` can cap the long side at `MAX_DECODE_SIDE`, falling back to the basic converter at native size. Audio pins only PCM + 16 bits and reads the rate/channels back, because demanding the device's exact layout makes some decoders refuse outright; `audio::resample::LinearResampler` covers the difference. Seeking is `SetCurrentPosition` with a `VT_I8` `PROPVARIANT` (`video::mf::propvariant_i64`) and the time format spelled as `GUID::from_u128(0)` — `GUID_NULL` sits behind a Cargo feature this crate does not enable. MF lands on the preceding keyframe, so `read(pixels_from, ..)` returns pre-roll frames as `Packet::VideoSkipped` **without** converting them, which is what makes a seek land in ~100 ms.
- `output.rs`: a stereo `Ring` drained by a cpal output stream — the mirror of `audio::capture`, which only ever opens *input* streams. The ring counts frames it actually **played**: silence written during an underrun does not count, so the clock stalls instead of running ahead of the decoder.
- `worker.rs`: the thread that owns both. Never *blocks* on the frame queue (an occluded window stops repainting, and a worker parked on a full queue would starve the audio device with it); it holds a backlog of `held_cap` frames instead, sized to buy about as much time as `HIGH_WATER_MS` of audio — get that asymmetry wrong and video falls behind the audio clock and the GUI drops most of what was decoded.
- `Clock`: with audio the device is master (`position = base + played/rate`, interpolated from the instant of the last callback and clamped to one buffer, since `played` only moves once per callback); without audio it is a wall clock that stops on pause. Every seek bumps `Shared::seq` and frames carry it, so frames already in flight when the user seeks are discarded rather than shown.
- Frame steps seek in **both** directions from the pts of the frame actually on screen (carried in `Command::Step`); "decode the next packet" would overshoot, because the reader runs a third of a second ahead of the GUI.

### `src/capture/` — platform backends behind one interface

`capture::start(CaptureConfig, epoch, FrameSink) -> CaptureHandle`. `Source` is `Monitor{id}` / `Window{id}` / `Region{monitor_id, rect}` with physical-pixel `Rect`s. Backend selection is `cfg(windows)` → `windows.rs` vs. `xcap_backend.rs` (xcap video recorder for monitors, screenshot polling for windows). `windows.rs` bypasses `windows-capture`'s `Frame::buffer()` (which creates a staging texture and does a blocking `Map` per frame): `Readback` keeps two staging textures, copies the wanted rectangle (`CopySubresourceRegion` + `Flush`) into one and maps the other (previous frame, `D3D11_MAP_READ`), copying rows into a `FramePool` buffer — one frame of latency, no GPU stall, one CPU copy. WGC throttles delivery itself where `is_minimum_update_interval_supported()` (Windows 11); otherwise a `PhaseLimiter` picks frames on the fps grid. The interval handed to WGC is a *floor*, so it comes from `capture::min_update_interval` (`0.85/fps`, the same slack `FpsLimiter` uses): asking for exactly `1/fps` leaves ~33 ns of margin against two vsyncs on a 60 Hz panel and snaps delivery to three, i.e. 20 fps instead of 30. The delivery thread runs at above-normal priority. **Every optional WGC setting is probed before the session is built** (`supported()` in `windows.rs`): asking for one the OS does not know makes `windows-capture` refuse to start, which is how `DrawBorderSettings::WithoutBorder` broke every capture on Windows 10 (`BorderConfigUnsupported` — `GraphicsCaptureSession.IsBorderRequired` is Windows 11 only, as `IsCursorCaptureEnabled` is 2004+). `border_setting` / `cursor_setting` fall back to `Default`, and the reason travels to the status strip through `CaptureHandle::take_note` → `Stats::add_note`. `OPENCLIP_LEGACY_WGC=1` forces that path on any machine. `monitors.rs` uses `xcap` on **every** platform for enumeration, one-shot screenshots (picker backdrop, previews) and `source_origin` (needed to map global mouse coords into the frame). WGC only delivers frames when the screen changes, so `frames_captured` is normally well below `fps × seconds`; repeats fill the gaps.

### `src/video/`

- `encoder.rs`: the `VideoEncoder` trait (`encode(FrameInput, pts) -> Vec<EncodedFrame>`, `flush`, `codec_params`, `is_hevc`, `input_layout`), `EncodedFrame` (**Annex-B**, parameter sets in-band on keyframes), `CodecParams` (H264 SPS/PPS or HEVC VPS/SPS/PPS, `from_annexb` harvests them), `EncoderRequest`, `EncoderInfo` / `Vendor` (an enumerated MF encoder), `available_encoders()` / `refresh_encoders()` and `create_video_encoder()` — tries the requested MF encoder, then others of the same family (hardware first), then OpenH264, returning a note. Not `Send`: encoders live on the encode thread.
- `openh264.rs`: OpenH264 in screen-content real-time mode (quality or CBR rate control, profile, keyframe interval, `Complexity::Low`, `cores/4` clamped to 2–4 threads — more threads measured *slower* on a hybrid P/E-core laptop and starve the GUI; `OPENCLIP_OPENH264_THREADS` overrides). Budget ~35 ms per 1080p frame on a laptop, i.e. it cannot sustain 1080p30 — `VideoCodec::Auto` prefers hardware.
- `mf/` (Windows): `mod.rs` — `ComGuard`, `startup()`, `MFTEnumEx` enumeration of hardware (`HARDWARE|ASYNCMFT`) and software (`SYNCMFT`) transforms with vendor labels, dedupe, a `probe()` that drops transforms which cannot negotiate a 720p output type (Microsoft's DX12 encoders), cached list; `transform.rs` — `MftSession`, a synchronous-style wrapper that also drives the async event protocol (`METransformNeedInput` credits, `HaveOutput`, drain, `MF_E_TRANSFORM_STREAM_CHANGE` renegotiation — after which an async MFT must *not* be polled again until its next HaveOutput event); `video.rs` — `MfVideoEncoder`: output type first (subtype, bitrate, size, rate, profile), `ICodecAPI` (rate control, GOP, **B-frames = 0** because the muxers assume PTS == DTS, low latency), NV12 input type, memory-buffer `IMFSample`s, keyframe from `MFSampleExtension_CleanPoint`, parameter sets from the stream or `MF_MT_MPEG_SEQUENCE_HEADER`.
- `convert.rs`: `RawFrame` (BGRA/RGBA + pts + optional mouse snapshot) and `Converter` (→ I420 or NV12 via the SIMD `yuv` crate, plus `downscale_half`). `scale.rs`: `Scaler` (`fast_image_resize`, bilinear ≤ 2×, box beyond).
- `mouse_fx.rs`: `MouseFx` settings (serde), `MouseSampler` (global pointer via `device_query`), and the painters for cursor sprite / click ripples / highlight halo. `mapped(origin, (sx, sy))` takes a per-axis scale because output sizes may be non-uniform. Effects are painted onto frames in the encode thread **and** in the live preview so the two always match. At `cursor_size == 100` the native cursor from the capture API is used; any other size hides it and draws the scalable arrow.
- `preview.rs`: downscaled `PreviewImage` for the GUI.
- `thumbnail.rs`: reads finished files back for the library — `probe(path, max_side)` returns a `MediaInfo` (running time + poster frame). Durations come from the container itself (`mvhd` for MP4/MOV, `avih` plus OpenDML `dmlh` for AVI) so they work everywhere; pictures are decoded with the `image` crate; on Windows an MF source reader (`MF_SOURCE_READER_ENABLE_VIDEO_PROCESSING`, RGB32 out, honouring a negative `MF_MT_DEFAULT_STRIDE`) supplies the first video frame and any duration the parsers missed. Non-Windows videos get no poster and the GUI falls back to an icon.

### `src/audio/`

`capture.rs` opens cpal streams (mic, or WASAPI loopback for system audio) that push timestamped `Chunk`s into a `SharedQueue`. `mixer.rs` places chunks on the recording timeline by arrival time, fills gaps > 60 ms with silence (WASAPI loopback goes quiet when the system is silent), resamples (`resample.rs`, linear) to the master rate as stereo and sums sources. `encoder.rs` is the `AudioEncoder` trait (`AudioFrame`, `AudioCodecConfig` for the container, `create_audio_encoder` with AAC → MP3 fallback); `mp3.rs` wraps LAME and splits its output so **each container sample is exactly one 1152-sample MP3 frame**; `pcm.rs` emits 16-bit LE 20 ms chunks (AVI only); `mf_aac.rs` (Windows) drives the Media Foundation AAC encoder (16-bit PCM in, raw 1024-sample AAC-LC out, AudioSpecificConfig from `MF_MT_USER_DATA`, 2112 priming samples skipped like MP3's `CODEC_DELAY_SAMPLES`).

### `src/mux/`

- `mp4.rs`: streaming, non-fragmented MP4: `ftyp` | 64-bit `mdat` (samples interleaved in ~0.5 s chunks) | `moov` written at `finalize`. `push_video` takes Annex-B, strips parameter sets / AUDs and length-prefixes; `VideoCodecConfig::{H264, Hevc}` selects `avc1`/`avcC` or `hvc1`/`hvcC` (`hevc.rs` parses the SPS profile_tier_level); `AudioCodecConfig` selects the `esds` object type (MP3 0x6B / AAC 0x40 + DecoderSpecificInfo); PCM is refused. Per-sample durations come from real pts (video timescale 90 000), keyframe table (`stss`), `co64` offsets.
- `avi.rs`: OpenDML AVI writer: fixed-size `hdrl` (rewritten at finalize) with `avih`, `strh`/`strf` (`H264`/`HEVC` fourcc; MP3 `0x0055` + `MPEGLAYER3WAVEFORMAT`, AAC `0x00FF` + ASC, PCM `0x0001`), reserved `indx` super-indexes, `odml/dmlh`, `JUNK` pad; `movi` chunks (`00dc`/`01wb`), ≤ ~1 GiB `RIFF` with `AVIX` continuations, `ix00`/`ix01` standard indexes per RIFF, legacy `idx1` for the first RIFF. Video is slot based: `slot = round((pts − first) · fps)`, gaps get empty `00dc` chunks, a taken slot returns `false`.
- `muxer.rs`: `Muxer` enum over both writers used by the pipeline. `boxes.rs` is the MP4 box-writing helper, `avc.rs` Annex-B ↔ AVCC and SPS/PPS, `hevc.rs` HEVC NAL types + SPS parser. `tests/mp4_roundtrip.rs` (independent `mp4-atom` parser, plus synthetic HEVC/AAC entries) and `tests/avi_roundtrip.rs` (hand-written RIFF walker) validate output — extend them when changing layouts.

### `src/ui/` — egui application

`App` (in `mod.rs`, the largest file) owns all settings and a `State` enum: `Idle` / `Picking(Picker)` / `Recording(Recorder)`. Layout (iOS-style dark, flat — see `theme.rs` / `widgets.rs`) is a header (segmented Region / Monitor / Window control, input tiles, snapshot / compact buttons, pause, REC) and a status row with a tinted capsule on top, a 200 pt sidebar (Home / General / Video / Image / About) on the left, pages built from `section_header` + `Card` inset-grouped lists in the centre (General and Video use a `segmented` tab row instead of scrolling) and a one-line footer (message on the left, app version on the right). Sub-modules extend `App` via `impl App` blocks:

- `format_dialog.rs`: the **Format settings** dialog, opened for one `FormatSection` (Video or Audio — the Video / Audio rows on the Video page and the ⚙ menu in the mini bar open the matching half; both halves show the File Type segmented control): a draft `FormatSettings` normalized on every change and committed on OK (`DialogOutcome::Ok` → `App::save_settings`). In the full window it is an `egui::Modal` with `sheet_frame()`; in compact mode the 72 pt bar cannot host a sheet, so `show(.., compact = true)` renders the same `body` in its own always-on-top `show_viewport_immediate` window (closing it cancels). Nested "…" modals for bitrate/keyframe and encoder details (with rescan). Opened from the Record tab's Settings button and the mini bar's ⚙; shown last in **both** `App::ui` branches.
- `picker.rs`: region selector — one undecorated always-on-top viewport per monitor showing a fresh screenshot; drag a rect, Esc cancels.
- `minibar.rs`: **compact mode** — the main viewport is resized into a single flat always-on-top bar (`enter_compact` / restore): source menu + target, dimensions, input tiles, ⚙, then a right-aligned status capsule (timer · size while recording, "Starting in n", or the last saved-file / error message for 5 s), pause and REC. Widths come from the content; if localized labels would make the left and right clusters collide the bar grows once (`App::bar_size`, which `place_bar_near_region` also uses). Debug builds honour `OPENCLIP_START_COMPACT=1` to open straight into the bar, `OPENCLIP_START_REGION=x,y,w,h` to preselect a region on the first monitor, and `OPENCLIP_OPEN_VIEWER=<path>` to open a file in the media viewer (all for screenshots, since none of them can be driven from a script). Closing the bar window restores the full window rather than quitting (`intercept_close`), at `ui::WINDOW_SIZE` — the same size the app opens at, which is also its minimum. `place_bar_near_region` parks the bar beside a freshly picked region **once**; the bar and the region are otherwise independent, so dragging either leaves the other where it is.
- `region_frame.rs`: the Camtasia-style border around the selected region, shown while compact for a region source (closing the bar closes it too), never while the picker is open. Child viewports can't be transparent with wgpu/DX12 on Windows, so it is four opaque `BAND_PT`-thick strip viewports placed a `GAP_PX` *outside* the rect (so they're never captured), and each strip **is** the line: filled edge to edge with the border colour (`theme::REGION` idle, `RED`/`ORANGE` recording/paused), so no matte band or dash gap is left for an opaque window to give away. On top of that go the white handles it owns (`HANDLE_PT` long along the strip, the full thickness across) — the horizontal strips span the full outer width and carry the corners plus the N/S midpoints. A fifth viewport is the centre crosshair; it sits *inside* the rect and is only shown while recording if `WDA_EXCLUDEFROMCAPTURE` took (`frame_excluded`). `style_overlay` applies that, the DWM squaring-off and `WS_EX_NOACTIVATE` (so grabbing the border doesn't steal focus) once per window set (`frame_styled` / `frame_parts`). It also kills the drop shadow DWM would otherwise draw around every strip — winit keeps `WS_CAPTION` on undecorated windows, so the fix is `DWMWA_NCRENDERING_POLICY = DWMNCRP_DISABLED` *and* clearing `WS_CAPTION | WS_THICKFRAME | WS_BORDER` (then `SetWindowPos(SWP_FRAMECHANGED)`); the strips are never snapped or resized by the user, so the styles cost nothing. The strips are **not** click-through: `grab_at` maps a press to `Grab::Move` or a resize, and the drag runs off the *global* pointer (`GlobalPointer`, `device_query`) because the windows move out from under the cursor — `dragged_rect` clamps to the monitor, keeps even dimensions and a 16 px minimum. Handles only appear in `State::Idle`; while recording (or counting down) the whole line moves the region and `App::apply_region` pushes the new origin to `Recorder::set_region`. The mini bar is not dragged along — the two are independent.
- `library.rs`: file browser model for the output folder (Videos / Images / Audios tabs; drawn by `mod.rs::library_panel`). Each `Entry` carries size, `modified` (the sort key) and `created` (what the list shows).
- `viewer.rs`: the **media viewer** the library's Play button and row double-click open (`App::open_viewer`). It takes the whole window — toolbar, status strip, navigation and footer are all skipped — with its own header (back · name + details · reveal / delete / close), a media area and a transport bar; Esc, Space, ←/→ (±5 s) and `,`/`.` (frame step) are bound. Video and audio drive a `crate::player::Player`; pictures decode straight to a texture with `player::load_image` and get a fit ↔ 1:1 toggle instead of a transport. The scrubber previews while dragged and only seeks every `SEEK_THROTTLE`, because every mouse move would re-decode from a keyframe. Snapshot writes the decoded frame through the same `timestamped` / `saved` path as the toolbar's. **While a recording is running, and in compact mode, the viewer is not used** — `open_viewer` falls back to `open_with_default`, since playing a file back mid-capture would feed the sound into the system-audio track and fight the encoder for the CPU.
- `thumbs.rs`: the poster-frame cache behind that list. One background thread runs `video::thumbnail::probe`; `get` queues a file the first time its row is drawn and returns `None` until the answer lands, `poll` (called from `ui()`) uploads finished images as textures. Entries are keyed by path *and* size + mtime, so the recording in progress is re-probed as it grows; `retain` drops textures for files that are no longer listed.
- `theme.rs`: the iOS dark palette (`BG` / `CARD` / `FILL*` / `SEPARATOR` / `LABEL*` / `BLUE` / `RED` / `GREEN` / `ORANGE`), `apply_theme` (visuals, spacing, text styles: Body 13, Small 11, Heading 20 semibold) and `install_fonts` (Inter Regular as the proportional face, Inter SemiBold as `FontFamily::Name("semibold")` via `semibold()` / `heading()`, Font Awesome appended as a glyph fallback). `icons.rs` holds the glyph constants; fonts live in `assets/fonts`.
- `widgets.rs`: the building blocks — `Card` (rows with inset hairlines: `row` lays controls out right-to-left, `row_inline` left-to-right, `text_row`, clickable `nav_row` with chevron, `custom` / `flush`), `section_header`, `footnote`, `segmented`, `switch` / `switch_row`, `primary_button` / `tinted_button(_small)` / `gray_button` / `destructive_button`, `icon_tile` / `icon_toggle` / `icon_button`, `rec_button(_sized)` + `RecMode` / `RecClick`, `pause_button`, `status_capsule` (+ `capsule_width_for` for jitter-free timers) / `capsule_button` / `Tint`, `nav_entry`, `vdivider`, `sheet_frame` (modal frame). Dialogs use `egui::Modal::new(..).frame(sheet_frame())`.
- `updater.rs`: update UI on top of `crate::update` — `start_update_check` (spawned from `App::new` when `check_updates`, and by the About / General "Check for updates" button), `poll_update` (called at the top of `ui()`), the `Update to vX` chip in the status strip's Idle arm, `about_update_rows` (the start-up toggle + check row, on the About page), and `update_dialog` (release notes, Download and install → progress bar → Restart now; falls back to "Open release page"), shown last in the full layout only.

`App::new` loads `Settings` and starts the encoder scan on a background thread (`encoder_rx`, polled each frame; `wait_for_encoders` blocks briefly before recording or opening the dialog so a saved GPU codec is not downgraded). REC goes through `start_recording` → `State::Countdown { started }` (when enabled; `tick_countdown` runs at the top of `ui()` and calls `start_recording_now` *before* drawing so the overlay never reaches the file; Esc / REC / the overlay button cancel) → `State::Recording`. `rec_button` takes a `RecMode`. `LivePreview` runs a separate low-fps capture (`20` fps) only while the Home → Preview tab is visible (it keeps running during the countdown); it is stopped on compact mode and on exit. `poll_preview` tells the recorder whether previews are wanted. `MouseFx` is shared with the encode thread as `Arc<RwLock<MouseFx>>` so edits in the Mouse tab apply live.

## Conventions and gotchas

- All coordinates in `capture` are **physical pixels**; egui works in points. Convert via the monitor's scale factor (see `region_frame.rs` / `minibar.rs`) when placing viewports around a `Rect`.
- Windows-only code lives under `#[cfg(windows)]` in `capture/windows.rs`, `video/mf/`, `audio/mf_aac.rs`, `build.rs` (icon embedding via `winresource` and the `/EXPORT:NvOptimusEnablement` / `AmdPowerXpressRequestHighPerformance` linker args for the statics in `lib.rs` — without them the NVIDIA encoder fails to activate on hybrid laptops) and a few DWM calls in `ui`; keep non-Windows builds compiling (`xcap_backend.rs` path, empty encoder lists) when touching shared interfaces.
- Both muxers assume **presentation order == decode order** (no `ctts`, no DTS): every encoder must run without B-frames.
- Media Foundation objects are thread-affine and `!Send`: create and use an encoder on one thread with a `ComGuard` (MTA) alive; the GUI thread is an STA, so enumeration runs on a helper thread.
- Encoders emit Annex-B; only the MP4 writer converts to length-prefixed samples. AVI keeps parameter sets in-band.
- Windows' AVI source (Media Foundation) reads the OpenDML `indx` super-indexes and interprets their `dwDuration` as PCM sample frames for audio streams (even MP3); a chunk count there makes the audio stream appear empty. `cargo run --example probe_media -- file` decodes a file through Media Foundation to catch this class of problem.
- If a captured window is resized mid-recording, the encoder is not re-negotiated: at `SizeMode::Full`/`Half` there is no `Scaler`, so `Converter::convert` bails and the encode thread aborts the recording with an error; at `Preset`/`Percent` the frame is silently rescaled to the fixed output and the aspect ratio distorts.
- A **region** may be moved while recording — the UI writes into a `capture::LiveRect` (x/y/w/h packed into one atomic so a frame never sees a half-applied drag) that the backends re-read per frame, and `Recorder::set_region` deliberately keeps `width`/`height`, so the frame size the encoder, converter and container header were built from never changes. Resizing is therefore a UI-side restriction (`region_frame.rs` hides the handles), not something the pipeline enforces. The encode thread recomputes the mouse-effect `origin` from the live rect so cursor and click overlays stay aligned as the region moves.
- Output files are `<prefix>-YYYYMMDD-HHMMSS.<mp4|avi>` in the output folder (default `~/Videos`); snapshots are PNG alongside.
- `docs/` is the GitHub Pages site (`index.html` + screenshots), not developer documentation. It has its own localization: translatable nodes carry `data-i18n` (textContent), `data-i18n-html` (innerHTML) or `data-i18n-alt`/`-title`/`-aria-label`, English stays in the markup as the fallback, and the header language dropdown swaps them from the inline `I18N` table (`?lang=xx` in the URL wins so shared links keep their language, then the `localStorage` choice, then `navigator.languages`; picking a language rewrites the URL with `history.replaceState`).
